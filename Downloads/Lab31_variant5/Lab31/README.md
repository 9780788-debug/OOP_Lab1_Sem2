# Лабораторна робота 3.1 – варіант 5

**Тема:** робота з файлами (потоки C#) та проєктування зв'язків між сутностями.

**Варіант 5**

| | |
|---|---|
| Сутність `Student` | Прізвище, Курс, Студентський квиток, Середній бал, Країна, Номер залікової книжки (+ Ім'я, бо `FirstName` обов'язковий для всіх сутностей за загальними вимогами) |
| Операція | Обчислити кількість студентів 3-го курсу, які проживають в Україні. Отримати їх дані з файлу |
| Додаткові сутності | `McdonaldsWorker`, `Manager` |
| Додаткове вміння | Грати в шахи (`PlayChess()`) |

## Запуск

Потрібен .NET SDK 8 (для іншої версії змініть `TargetFramework` у обох `.csproj`).

```
dotnet run --project Lab31.App
dotnet run --project Lab31.App -- шлях/до/файлу.txt     # інший файл даних
```

За замовчуванням дані зберігаються в `data/people.txt` (створюється автоматично).

**Швидка демонстрація:** пункт меню `3` (завантажує 10 осіб різних типів) → `7` (відповідь варіанту: **3** студенти) → `4`/`5` (пошук) → `8` (дії Study/Teach/PlayChess) → `6` (видалення) → `1` (перегляд файлу).
Приклад файлу, який створює програма: `docs/example-people.txt`.

## Структура рішення

```
Lab31.sln
├── Lab31.Storage      ← ТІЛЬКИ читання/запис файлу (жодних даних предметної області, жодної консолі)
│   ├── IRecordStorage / IRecordReader / IRecordWriter    (абстракції)
│   └── TextFileRecordStorage / TextRecordReader / TextRecordWriter  (StreamReader/StreamWriter над FileStream)
└── Lab31.App
    ├── Domain      Person (abstract), Student, McdonaldsWorker, Manager, CountryNames
    │   └── Skills  ISkill, ILearner (Study), ITeacher (Teach), IChessPlayer (PlayChess) + StudySkill, TeachSkill, ChessSkill
    ├── Metadata    AttributeSpec (regex-валідація, обов'язковість), IPersonDescriptor, PersonDescriptor<T>, *Descriptor, PersonTypeRegistry
    ├── Actions     IPersonAction + StudyAction, TeachAction, PlayChessAction
    ├── Services    PersonRepository (файл ↔ об'єкти), PersonService (додавання, пошук, видалення, завдання варіанту)
    ├── UI          ConsoleMenu – єдиний клас, що працює з консоллю
    ├── Demo        DemoDataProvider – набір вхідних даних (10 осіб)
    └── Program.cs  composition root (єдине місце, де вибираються конкретні класи)
```

Діаграми класів: `docs/class-diagram-domain.png` (сутності, вміння, дії) і `docs/class-diagram-architecture.png` (шари та залежності).
Джерела діаграм: `*.dot` (Graphviz) та `*.mmd` (Mermaid).

## Формат файлу (один файл для всіх типів)

```
Student IvanPetrenko
{ "firstname": "Ivan",
  "lastname": "Petrenko",
  "course": "3",
  "studentId": "KB123456",
  "averageGrade": "85.5",
  "country": "Україна",
  "gradebookNumber": "20210001"};

Manager NataliaKravchenko
{ "firstname": "Natalia",
  "lastname": "Kravchenko",
  "employeeId": "MG00001",
  "department": "Operations"};
```

Читач також розуміє типографські лапки “ ” з методички. Дані читаються й записуються **поелементно**
(`WriteAttribute` / `ReadAttribute`), об'єкти цілком у файл не передаються.

## Відповідність вимогам

| Рівень | Що зроблено |
|---|---|
| Задовільно | Сутності за варіантом; файлові операції та ввід-вивід – в окремих класах, не в бізнес-сутностях; введення ≥ 6 осіб, вивід, видалення, пошук за прізвищем та унікальним ідентифікатором; завдання варіанту; regex для студентського квитка, залікової книжки, імені/прізвища/країни/курсу/середнього балу/табельного номера; **жодних колекцій** (тільки масиви) |
| Добре | Файлові операції в окремому проєкті `Lab31.Storage`; весь ввід-вивід на екран – у `ConsoleMenu`; абстракції (інтерфейси та абстрактні класи) для зв'язків між сутностями |
| Відмінно | Нову сутність (Pupil, Musician…) додає новий клас + дескриптор + один рядок у `Program.cs`; нову поведінку (Play(), Drive()…) – новий skill + action + один елемент масиву в `Program.cs`. Існуючі класи (`Person`, `Student`, `ConsoleMenu`, репозиторій, сервіс, сховище) **не змінюються** |
| Підвищена складність | Один файл-джерело для всіх типів сутностей |

Принципи: **composition over inheritance** (поведінка `Person` складається з `ISkill`-об'єктів, наслідування лише для спільних даних),
**low coupling / high cohesion** (сховище нічого не знає про сутності), **IoC** (усе залежить від інтерфейсів, залежності передаються в конструктори, збирає їх `Program.cs`).

## Прийняті припущення

* Додано атрибут `FirstName` (за загальною вимогою «обов'язкові атрибути кожної сутності: FirstName, LastName»).
* Середній бал – за 100-бальною шкалою (0–100, крапка як роздільник).
* Формати: студентський квиток `KB123456` (2 великі латинські літери + 6 цифр), залікова книжка – 8 цифр, табельні номери `MC#####` (працівник) і `MG#####` (менеджер). За потреби змініть у `Metadata/Patterns.cs`.
* Країна порівнюється без урахування регістру; «Україна» та «Ukraine» вважаються однією країною.
* Обов'язкові атрибути: усі, крім `restaurant` (McdonaldsWorker) та `department` (Manager) – для них діють значення за замовчуванням `Unknown` / `General`.
* Дії Study/Teach/PlayChess змінюють стан об'єкта (лічильники) в межах сеансу; у файл ці лічильники не записуються.
* Уміння: Student – навчання в університеті + шахи; McdonaldsWorker – самонавчання; Manager – самонавчання + Teach() + шахи.

## Важливе

Код написано без можливості скомпілювати його в середовищі, де створювався (там немає .NET SDK), тому першу збірку варто зробити самостійно: `dotnet build`. Логіку формату файлу та регулярні вирази я перевірив окремо, але повний прогін програми потребує .NET.
